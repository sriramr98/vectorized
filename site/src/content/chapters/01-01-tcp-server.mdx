## What we will build

Vectorized begins as a TCP server. In this lesson we will build the part that accepts connections and manages their lifetime.

The result will be able to:

- listen for TCP connections;
- serve several clients concurrently;
- delegate each client to a handler;
- stop accepting clients when the process is shutting down; and
- wait for active handlers before the server exits.

This lesson follows commit [`af23438`](https://github.com/sriramr98/vectorized/commit/af23438). The code shown below comes from that commit.

## Define a connection handler

Create `transport/tcpserver/server.go`. Begin with a small interface for code that serves one connection:

```go title="transport/tcpserver/server.go"
// Package tcpserver provides the lifecycle for TCP listeners used by Vectorized.
package tcpserver

import (
    "context"
    "errors"
    "fmt"
    "io"
    "log/slog"
    "net"
    "sync"
)

// Handler serves one accepted connection. It should return when ctx is done or
// when the peer disconnects.
type Handler interface {
    ServeConn(context.Context, net.Conn) error
}
```

The TCP server will call `ServeConn` after accepting a client. Later, the public handler will read RESP requests from this connection. Keeping that work behind an interface lets the transport package focus on connection lifecycle.

Most handlers can be ordinary functions. `HandlerFunc` adapts a function to the interface:

```go title="transport/tcpserver/server.go"
// HandlerFunc adapts a function to a Handler.
type HandlerFunc func(context.Context, net.Conn) error

// ServeConn implements Handler.
func (f HandlerFunc) ServeConn(ctx context.Context, conn net.Conn) error {
    return f(ctx, conn)
}
```

This lets callers pass either a struct that implements `Handler` or a function with the same signature.

## Store the server state

The server needs the listener and handler supplied by its caller. It also needs to remember which clients are active so it can close them during shutdown.

```go title="transport/tcpserver/server.go"
// Server owns one listener and coordinates a graceful shutdown of its clients.
// It is protocol-agnostic: public clients and future replication clients can
// use the same server with different Handlers.
type Server struct {
    listener net.Listener
    handler  Handler
    logger   *slog.Logger

    mu      sync.Mutex
    closing bool
    conns   map[net.Conn]struct{}
    clients sync.WaitGroup
}
```

`conns` is a set of active connections. `mu` protects both the set and `closing`. They belong under the same lock because checking the shutdown state and adding a connection must happen together.

`clients` counts connection-handler goroutines. Shutdown will wait on it before returning.

The constructor initializes the connection set and supplies a default logger when the caller does not provide one:

```go title="transport/tcpserver/server.go"
// New creates a server around an already-created listener.
func New(listener net.Listener, handler Handler, logger *slog.Logger) *Server {
    if logger == nil {
        logger = slog.Default()
    }

    return &Server{
        listener: listener,
        handler:  handler,
        logger:   logger,
        conns:    make(map[net.Conn]struct{}),
    }
}
```

The caller creates the listener. Tests can therefore use an ephemeral port, while the real process can choose its address from command-line configuration.

## Start serving

`Serve` first validates the dependencies needed by the accept loop:

```go title="transport/tcpserver/server.go"
// Serve accepts connections until ctx is canceled or the listener fails. On
// shutdown it closes the listener and all active connections, then waits for
// every Handler to return.
func (s *Server) Serve(ctx context.Context) error {
    if s.listener == nil {
        return errors.New("tcpserver: listener is nil")
    }
    if s.handler == nil {
        return errors.New("tcpserver: handler is nil")
    }
```

`Accept` blocks while it waits for the next client. Cancelling `ctx` does not wake it. Closing the listener does, so register a callback that closes the listener when the context is cancelled:

```go title="transport/tcpserver/server.go"
    stopClosingListener := context.AfterFunc(ctx, func() {
        _ = s.listener.Close()
    })
    defer stopClosingListener()
    defer s.shutdown()
```

`context.AfterFunc` runs the callback after cancellation. The function it returns unregisters that callback when `Serve` finishes for another reason.

`shutdown` is deferred here so every exit from `Serve` performs the same cleanup.

## Accept clients

The main loop accepts one connection at a time and starts a goroutine for each admitted client:

```go title="transport/tcpserver/server.go"
    for {
        conn, err := s.listener.Accept()
        if err != nil {
            if ctx.Err() != nil || errors.Is(err, net.ErrClosed) {
                return nil
            }

            var netErr net.Error
            if errors.As(err, &netErr) && netErr.Temporary() {
                s.logger.Warn("temporary accept failure", "error", err)
                continue
            }
            return fmt.Errorf("accept TCP connection: %w", err)
        }

        if !s.track(conn) {
            _ = conn.Close()
            continue
        }

        s.clients.Add(1)
        go s.serveConn(ctx, conn)
    }
}
```

An error caused by cancellation or a closed listener ends the loop normally. A temporary network error is logged and retried. Other errors are returned to the caller.

The connection is tracked before its goroutine starts. The wait-group counter is also incremented before starting the goroutine, so shutdown cannot begin waiting before the client has registered itself.

`track` performs the shutdown check and map insertion under one lock:

```go title="transport/tcpserver/server.go"
func (s *Server) track(conn net.Conn) bool {
    s.mu.Lock()
    defer s.mu.Unlock()
    if s.closing {
        return false
    }
    s.conns[conn] = struct{}{}
    return true
}

func (s *Server) untrack(conn net.Conn) {
    s.mu.Lock()
    defer s.mu.Unlock()
    delete(s.conns, conn)
}
```

A connection accepted just as shutdown begins will either enter the active set before `closing` changes, or it will be rejected and closed by the accept loop.

## Serve one connection

The server owns every connection returned by `Accept`. The handler can concentrate on application behavior because `serveConn` performs the cleanup:

```go title="transport/tcpserver/server.go"
func (s *Server) serveConn(ctx context.Context, conn net.Conn) {
    defer s.clients.Done()
    defer s.untrack(conn)
    defer conn.Close()

    if err := s.handler.ServeConn(ctx, conn); err != nil && !errors.Is(err, io.EOF) && ctx.Err() == nil {
        s.logger.Debug("connection handler stopped", "remote_address", conn.RemoteAddr(), "error", err)
    }
}
```

The deferred calls run on every return path. They close the socket, remove it from the active set, and decrement the wait group.

EOF is the normal result when a client disconnects. A handler returning during context cancellation is also expected. The server logs errors only when neither condition applies.

## Shut down active clients

When `Serve` exits, `shutdown` prevents new connections from being tracked and takes a snapshot of the current connections:

```go title="transport/tcpserver/server.go"
func (s *Server) shutdown() {
    s.mu.Lock()
    if s.closing {
        s.mu.Unlock()
        return
    }
    s.closing = true
    connections := make([]net.Conn, 0, len(s.conns))
    for conn := range s.conns {
        connections = append(connections, conn)
    }
    s.mu.Unlock()

    _ = s.listener.Close()
    for _, conn := range connections {
        _ = conn.Close()
    }
    s.clients.Wait()
}
```

The connections are copied while the mutex is held. The mutex is then released before any socket is closed.

This ordering matters. Closing a connection causes its handler to return, and `serveConn` needs the same mutex to call `untrack`. Holding the mutex while waiting would prevent the handler from completing.

After closing the snapshot, `clients.Wait` keeps shutdown blocked until every registered handler has finished its deferred cleanup.

## Add the first public handler

The first handler does not understand a protocol. It keeps the connection open until the server context is cancelled:

```go title="handlers/public_handler.go"
package handlers

import (
    "context"
    "net"
)

func PublicTcpHandler(ctx context.Context, conn net.Conn) error {
    // Protocol handling will be installed here in a later episode.
    <-ctx.Done()
    return nil
}
```

This is enough to exercise connection acceptance and shutdown before introducing request parsing.

## Wire the server into `main`

The process creates the listener, converts operating-system signals into context cancellation, and starts the server:

```go title="main.go"
func main() {
    addr := flag.String("addr", ":6380", "TCP listen address")
    flag.Parse()

    logger := slog.New(slog.NewTextHandler(os.Stdout, nil))
    listener, err := net.Listen("tcp", *addr)
    if err != nil {
        logger.Error("listen failed", "address", *addr, "error", err)
        os.Exit(1)
    }

    ctx, stop := signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)
    defer stop()

    server := tcpserver.New(listener, tcpserver.HandlerFunc(handlers.PublicTcpHandler), logger)

    logger.Info("server listening", "address", listener.Addr())
    if err := server.Serve(ctx); err != nil && !errors.Is(err, context.Canceled) {
        logger.Error("server stopped unexpectedly", "error", err)
        os.Exit(1)
    }
    logger.Info("server stopped")
}
```

Run the version used by this lesson:

```bash
git switch --detach af23438

```

The server now accepts TCP connections on port `6380`. It will not send a response because protocol handling is the next lesson.

## Test the lifecycle

The main server test uses a real listener on an ephemeral loopback port. Its handler reports when it starts, waits for cancellation, and reports when it stops.

The test then:

1. starts `Serve` in a goroutine;
2. connects a client;
3. waits for the handler to start;
4. cancels the server context;
5. waits for the handler and server to stop; and
6. verifies that the client reads EOF.

Run the committed tests with the race detector:

```bash
go test -race ./transport/tcpserver
```

The package now has a complete TCP lifecycle. The next lesson will teach the public handler how to frame requests using RESP.
